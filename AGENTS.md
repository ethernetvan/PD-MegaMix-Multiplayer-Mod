## Multiplayer client: menus, input, song availability
- The game gives no signal for the cursor in the results end-menu or the pause menu (probed: no AET layer call, no PVGameData byte). `mp/MpMenu.cpp` tracks both blind: it counts the presses the game actually receives (after blocks/injects, debounced across Npad styles) and strips input it says can't land. Real anchors: StageResult init/dest, the `win_vp_in` layer (results page 2), `pv->paused` edges, pv_sel init. Details and timings: `docs/MULTIPLAYER_STATUS.md` Round 8.
- Rooms with 2+ members: Retry is swallowed in both menus (Lag Config/Options too in the pause menu); a retry that slips through is detected (song clock running after results with no pv_sel init) and undone via pause -> Return to Song List. Solo rooms are vanilla.
- `input::Apply` runs once per GetNpadState hook (Handheld/FullKey/JoyDual, called by the game and by `nc/input.cpp`) plus our merged poll: anything edge-based must combine the sources (see `MpInput.cpp`), otherwise a held button on a Pro Controller or sys-botbase looks like a new press on every poll.
- Plugin hotkeys (`ImGuiOverlay.cpp`): L3+R3 alone toggles the input display (`InputOverlay`) on RELEASE after a pure >= 0.8 s hold (no third button during it), Off -> Gamepad -> (Keyboard only with `enable_keyboard`) -> Off, with a system banner (`mp::lobby::SystemBanner`); the L3+R3+ZL/ZR/Plus/L/R combos still fire while held. `mp::lobby::DrawPanel()` runs every ImGui frame (returns early when closed) so the Edit Name / Join Room VirtualKeyboard closes whenever the overlay closes, including OnPvSelDest.
- pv_sel state 10 is entered both by a song start (8 -> 10) and by B back to the main menu (6 -> 10 -> Dest): only the 8 -> 10 edge means "start". Clear border: `PVGameData+0x2D0D0` = song+difficulty clear % (per song, e.g. 70 on an Extreme), `+0x2D0D4` = the running border that only reaches it at the last note (details in `docs/MULTIPLAYER_STATUS.md` Game facts).
- Which songs a console can select = the selector's `sorted_pv_lists` (sort mode x difficulty x edition, `SongQuickJump::PvSelectableAt`), not pv_db: pv_db lists every official song including DLC the console doesn't own.
- Module table (`mp/MpModuleDb.cpp`): hook on the gm_module_tbl parser `0x3c3980(db, kv)`; the merged table (vanilla + DLC + mods' `mod_gm_module_tbl.farc`) is a sorted vector at db+0x18/+0x20 of 0x40-byte entries (+0 key id, +0xC sort_index, +0x10 libc++ name (localized), +0x28 chara, +0x2C cos, +0x30 attr). chara: 0 MIKU 1 RIN 2 LEN 3 LUKA 4 NERU 5 HAKU 6 KAITO 7 MEIKO 8 SAKINE 9 TETO; defaults 0/40/41/42/2/1/45/44/43/283. Mods can REUSE official ids (the user's Mikudayo pack puts Mikudayo/Mikunano, chara HAKU, on 437/438 = official White T-Shirt MEIKO / Breadful T-Shirt). `admin.py module_dump` writes `module_tbl_dump.txt` to the SD root (song select).
- Avatars: each console announces `avatar {module, chara, mh}` (mh = FNV-1a of chara/cos/sort_index, language independent). `avatar::Resolve` shows, in order: this console's own image if its entry has the same signature; the owner's uploaded portrait only with `[multiplayer] remote_avatars = true` (opt-in, "Custom portraits" on the MP overlay's OPTIONS screen, opened by the gear button right of the status pill on HOME, `admin.py remote_avatars on|off`; downloaded with `avatar_get {img}` -> `avatar_px {img, rgba}`, exactly 96x96 RGBA base64, max 6 cached, 3 tries, never written to SD); else the chara's default module; else the silhouette. Crop: big heads (head band >= 0.31 x card width) blend to a crop of 1.2 x head width centred on the face (Mikudayo), others unchanged.
- Files open in the user's IDE (e.g. `AGENTS.md`, `Config.cpp`) don't get editor-tool edits on disk (they land in the unsaved editor buffer): patch them with a script and confirm with `git diff`/mtime before building.

## Online server (Render, `mikumod.evanthomas.dev`)
- `mp_server.py --cloud` (or `MP_CLOUD=1`; `render.yaml` at the repo root) opens ONE port (`--web-port`, default `$PORT` else 8080): dashboard, `/health`, browser `/ws` (also a WS upgrade on `/`), consoles on `/switch`. Game thread `mp::SetServerMode` / `mp::SetCloudUrl`: save config, leave the room, bump a generation the net thread polls. OFF: the net thread idles (state `off`) and, when booted in OFF, never even submits the nifm request or opens a socket (verified: no traffic for 10 min); the console then can't receive admin commands - restore with `mm-re/tmp/set_mode.py N local` + restart. ## Web spectator/admin UI — `server/web_bridge.py` + `web/`
- Bridge (stdlib, same process as `mp_server.py`): serves `web/dist`, `GET /api/state`, `GET /api/health`, `GET /api/avatar/<id>.png` (a console's uploaded portrait, stored per uploader and named by its content id = first 12 hex of the SHA-256 of the normalized pixels, at most 256 kept; uploads are admission-gated in `avatars.py` - `avatar_img` must be square RGBA 32..96 matching the client's announced module, at most 3 attempts/cid/60s, normalized to 96x96 with transparent-pixel RGB zeroed and served with nosniff/CSP/CORP headers; consoles may fetch one with `avatar_get` only for a member of their own lobby, 20/cid/60s; `--no-avatar-relay` keeps portraits web-only), WebSocket `/ws` (snapshot push every 200 ms on change, activity feed, `auth`/`action` messages; schema mirrored in `web/src/types.ts`). Flags: `--web-port` (0 disables; a busy port only disables the web UI), `--web-host`, `--web-token` (default random, printed at startup with a `?token=` link).
- Access: anyone on the LAN spectates. Interim login: typing the lobby owner's in-game name unlocks that lobby's host controls (kick, pick mode, assign/make picker); the admin token unlocks every lobby. Real accounts are designed in `docs/ACCOUNTS_DESIGN.md`.
- Browsers never see raw console cids (a cid is enough to hijack a console's session): members are `mid = HMAC(per-process secret, cid)[:12]`.
- Frontend: React 19 + Vite + TypeScript (strict), no other runtime deps. `cd web && npm ci && npm run build` (the server shows a "not built" page until `web/dist` exists). Checks: `npm run typecheck && npm test`.
- Styling follows the game's own visual language (see `mm-re/screens/m1b_menu1.png`, `v1c_sel2.png`, `ui_room.png`): design tokens in `styles.css` `:root`, chevron-tag bars, parallelogram chips, dark translucent data panels on a bright teal confetti backdrop. Player icons are hexagons via `components/HexAvatar.tsx` — currently gradient placeholders; pass `src` to show a real icon once the server sends one.
- Dev: `cd web && npm run dev` proxies `/api` + `/ws` to `MP_WEB_BACKEND` (default `http://127.0.0.1:8080`). Install new deps with exact pins and versions at least 7 days old (`npm install --save-exact --before=<date>`).
